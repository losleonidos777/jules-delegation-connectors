# Compatibility review - August 2026

## Scope

This review compared the connector with:

- Current Google Jules changelog and REST reference.
- MCP protocol 2025-11-25.
- Current Claude Code Desktop, plugin, and MCP documentation.
- Current Codex configuration and plugin examples.
- `davideast/modjules`.
- `gemini-cli-extensions/jules`.
- The public LobeHub Jules delegation skill.
- The requested MCP Market page (the exact page could not be retrieved; only overlapping public delegation patterns were considered).

## Official Jules changes reviewed

- Current REST/changelog: repoless sessions, complete git-patch outputs, immutable activity events, a server-side `createTime` range cursor, and single-activity reads. Because the generated method page omits the cursor, the connector also applies a defensive local filter.
- February 2: Jules gained curated outbound MCP integrations. This is a different direction from this project (Jules as an MCP-backed service), but it reinforces least-privilege and explicit credential boundaries.
- February 19: Jules added automatic CI repair for its own PRs and configurable commit authorship. These are account/service settings, so the connector documents them rather than duplicating the behavior.
- March 9: Gemini 3.1 Pro became available to Pro users. This is service-side and required no REST or MCP schema change.
- The current Sessions reference documents session deletion; the CLI retains it behind `--yes` and does not expose it as an implicitly callable MCP tool.

## Confirmed integration defects

### Codex plugin manifest

The previous Codex plugin stored TOML naming (`mcp_servers`) in JSON. Current plugin examples and plugin manifests use `mcpServers`. The server could therefore be present on disk but not registered as a plugin-provided MCP server.

Resolution: use `mcpServers`, keep JSON to documented stdio fields, and retain `[mcp_servers.jules]` plus `cwd`/timeouts only in Codex TOML examples.

### Claude Code Desktop environment

Desktop Local sessions do not reliably inherit arbitrary shell variables. The previous plugin referenced optional variables without defaults and provided no Desktop-specific secret setup guidance.

Resolution: use `${VAR:-default}` where appropriate, use `${CLAUDE_PLUGIN_DATA}` for persistent state, remove undocumented per-server fields, and document secret injection outside version control.

### MCP/API drift

The server was pinned conceptually to an older MCP lifecycle and missed newer Jules data shapes and endpoints. It also returned very large duplicated payloads.

Resolution: protocol negotiation, standard JSON-RPC errors, tool annotations, repoless support, local activity cursors, `getActivity`, `bashOutput`, compact snapshots, changed-file summaries, and per-file diffs.

## Best practices adopted

### From official Jules CLI and Gemini Jules extension

- Preflight install/auth/source checks.
- Automatic repository identification as a documented workflow.
- Clear separation between creating a task and polling/retrieving it.
- Treat the official Jules CLI as an interoperable backend for local pull/apply/teleport workflows, not a competitor to the REST connector.

### From modjules

- Separate lightweight session state/timeline queries from large artifact retrieval.
- Expose changed-code and shell-validation artifacts as dedicated operations.
- Keep LLM-facing results compact and analysis-oriented.
- Use local state/cache carefully for recoverability.

Not adopted: modjules defaults that auto-create PRs or skip interactive plan approval. This project keeps safer defaults.

### From the LobeHub Jules skill

- `doctor`-style installation/auth/repository connectivity checks.
- Preview results before applying them locally.
- Use a dedicated `jules/<session>` branch when applying official CLI output.
- Treat `AGENTS.md` as repository context and explicitly include build/test conventions.
- Poll until a terminal or human-input state, then stop.

### From delegation marketplaces

- Artifact-first results and durable run/state directories.
- Separate read-only inspection from write actions.
- Explicit timeouts, constrained scope, and review gates.
- Return concise summaries before large diffs.

## Deliberately retained safety policy

- Plan approval defaults to on for implementation sessions.
- Auto-PR remains opt-in.
- Review prompts explicitly request no edits and no PR creation, while documentation warns that this is not a hard sandbox.
- The connector never sends local credentials as prompt context.
- API writes are not automatically retried.
- The documented session-delete path is CLI-only and requires an explicit `--yes` confirmation; it is not exposed as an implicitly callable MCP tool.
- Mutating MCP tools require human interaction in Claude Code.

## Follow-up candidates

- Opt-in local git context injection (branch, recent files, commits, and staged paths) with strict size caps.
- Optional backend adapter around the official `@google/jules` CLI for `remote pull --apply` and `teleport`.
- Local immutable activity cache keyed by `createTime`, inspired by event-sourcing patterns.
- MCP task-augmented execution when Claude Code and Codex support it consistently.
- A signed release and marketplace distribution pipeline.

## Context-efficient artifact review

- List changed files before requesting a whole patch.
- Fetch one exact file diff when reviewing a focused finding.
- Keep full-patch export available in the CLI, but cap MCP responses to protect client context.
